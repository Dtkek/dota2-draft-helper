# Dota 2 Draft Helper

**Краткое описание:** Локальное веб-приложение, которое подсказывает, каких героев брать против вражеского драфта. Считает преимущество по матчапам, показывает мету по рангам и разбирает профессиональные матчи. Работает на публичном API OpenDota, без зависимостей.

---

## 1. О проекте

### 1.1 Основная информация

- **Тип проекта:** Инструмент для личного использования
- **Стадия:** Рабочая первая версия, все функции проверены на живых данных
- **Дата начала:** 2026-09-13
- **Команда:** 1 человек
- **Бюджет:** не применимо

### 1.2 Цели проекта

**Главная цель:** Во время фазы драфта быстро получать обоснованный ответ на вопрос «кого брать против вот этих героев», не доверяя ощущениям.

**Ключевые метрики:**
- Время от ввода вражеского драфта до рекомендации: секунды (данные кэшируются)
- Прозрачность: для каждой рекомендации видно, из чего сложился балл и на скольких играх он основан
- Ноль зависимостей: запуск одной командой на чистом Python

### 1.3 Проблема и решение

**Проблема:** Решение в драфте принимается за секунды, а данные о матчапах разбросаны по сайтам, часть из которых закрыта подпиской. Плюс сырые винрейты матчапов почти всегда основаны на маленькой выборке, и доверять им как есть нельзя.

**Решение:** Локальное приложение, которое тянет матчапы из OpenDota, применяет статистическое сглаживание под объём выборки и показывает разбор балла: сколько дал контрпик, сколько — базовая сила героя.

**Альтернативы:** d2pt.com и Dotabuff показывают похожие данные, но d2pt закрыт от автоматического сбора и частично платный, а сырые «advantage» без поправки на выборку вводят в заблуждение.

2. Потенциально — знакомые из той же пати, если приложение окажется полезным

### 2.2 Бизнес-модель

Не применимо — инструмент для себя, не продукт.

### 2.3 Ценностное предложение

**Ключевые работы (Jobs To Be Done):**
1. «Понять за 10 секунд, кого брать против этого драфта» — топ героев с фильтром по роли
2. «Не обмануться шумом» — сглаживание и явный показ объёма выборки

**Уникальное преимущество:** Числа не выдаются за истину. Видно объём выборки, вклад каждой составляющей и значение сглаживания.

## 3. Контекст и важные детали

### 3.1 Технический стек

- Python 3 (стандартная библиотека: `http.server`, `urllib`, `json`) — никаких пакетов
- Фронтенд: обычные HTML/CSS/JS без сборки и фреймворков
- Кэш ответов API — файлы в `app/.cache`
- Данные: OpenDota API (публичный, без ключа)

### 3.2 Ключевые особенности

- Все материалы и комментарии в коде — на русском (`project_language: Russian`).
- Слой источников данных сменный: интерфейс `HeroSource`, активный источник выбирается одной строкой в `app/sources/__init__.py`. Это заготовка под STRATZ.
- Сглаживание матчапов оценивается по самим данным, а не задано константой.
- Оценка матчапов усредняется по врагам, а не суммируется: сумма подразумевала бы независимость эффектов и завышала бы результат в разы.

### 3.3 Ограничения и риски

**Ограничения:**
- **d2pt.com как источник отпадает.** В `robots.txt` сайта `Disallow: /` для ClaudeBot, GPTBot, CCBot и др., плюс сигнал `ai-train=no`; сайт за Cloudflare, данные частично по подписке. Скрапер не писался осознанно.
- Нет синергии союзников — OpenDota не отдаёт винрейты пар героев в одной команде.
- Нет разбивки по позициям: керри и саппорт одного героя неразличимы.
- Ранг Immortal недоступен: поле `8_pick` у OpenDota пустое.
- Про-мета как отдельный режим не показывается: `pro_pick` по всем героям даёт около тысячи игр.

**Риски:**
- Изменение схемы OpenDota сломает разбор ответов → источник изолирован в одном модуле, чинится в одном месте.
- Лимит 60 запросов в минуту → кэш на диске с разным TTL по типам данных.
- Соблазн доверять баллу как точному прогнозу → в интерфейсе показывается объём выборки, пары с n < 15 приглушены.

## 5. История изменений

### 2026-09-13 — Чтение экрана и поддержка Windows

Приложение научилось само узнавать героев на экране драфта и подставлять их в подбор. Распознавание двухфазное: калибровка полным поиском по кадру (~4 с, один раз за драфт) и слежение по известным прямоугольникам (0,1 мс на кадр). Добавлен `start.bat` для Windows: сам находит Python и ставит пакеты.

Что пришлось исправлять по ходу, каждый раз по результатам замеров:

1. **Выбор масштаба «по сумме совпадений»** всегда выигрывал самый мелкий шаблон — он даёт кучу ложных откликов. Заменено на среднее по нескольким лучшим совпадениям.
2. **Калибровка занимала 15 секунд.** Перебор масштабов перенесён на уменьшенный кадр, в полном разрешении остался один проход. Стало 4,3 с.
3. **Ложные срабатывания на постороннем экране.** Порогом уверенности не отделялись: настоящий герой на мелком портрете набирал 0,69, а случайное совпадение — 0,74. Решило сочетание трёх признаков: цвет (сравнение по цветной подписи плюс проверка насыщенности), геометрия (портреты драфта стоят в ряд, мусор разбросан) и минимальный размер портрета. На постороннем экране стало ноль ложных срабатываний.

Проверено: классификация 40 из 40 на синтетических кадрах, ноль ложных срабатываний на реальном рабочем столе. **Не проверено: настоящий экран драфта Dota 2 и запуск под Windows** — под рукой не было ни игры, ни Windows.

### 2026-09-13 — Проект создан, написана первая рабочая версия

Согласован формат (локальное веб-приложение) и источник данных (OpenDota со сменным слоем под STRATZ). Написаны сервер на стандартной библиотеке, модель подбора и интерфейс на три вкладки: драфт, мета, про-матчи.

### 2026-09-13 — Исправлены три ошибки модели, найденные на живых данных

Первая версия выдавала преимущества до +87 процентных пунктов, что невозможно. Разбор показал три отдельные причины:

1. **Неверная база для матчапов.** Использовались `pro_win/pro_pick` из heroStats, а там почти нет данных: у Juggernaut 3 игры из 3, то есть «база» 100%. Теперь базовый винрейт считается по той же таблице матчапов, из которой берутся сами матчапы.
2. **Неверно определён источник матчапов.** Считалось, что это про-матчи; на деле публичные — у Juggernaut 9400 игр, суммарный винрейт 51,76% совпадает с пабным 51,92%. Документация в коде исправлена.
3. **Молчаливая подмена ранга.** При запросе ранга без данных (Immortal, `8_pick` пустое) код незаметно подставлял общую публику. Теперь подмены нет, а API возвращает поле `note` с пояснением.

Дополнительно: сглаживание `K` больше не задано константой 40, а оценивается по разбросу самих данных (эмпирический байес, около 50–70 на текущих данных); оценка матчапов усредняется по врагам вместо суммирования; вклады в таблице показываются с весами, чтобы колонки складывались в итоговый балл.
