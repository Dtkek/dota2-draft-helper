# Драфт-хелпер Dota 2

Локальное веб-приложение: подсказывает, кого брать против вражеского драфта,
показывает мету по героям и разбирает профессиональные матчи.

## Запуск

**Windows, без Python:** скачать `dota2-draft-helper-windows.zip` со страницы
<https://github.com/Dtkek/dota2-draft-helper/releases/tag/latest>, распаковать
и запустить `dota2-draft-helper.exe`. Внутри уже всё: Python, OpenCV, numpy.
Архив пересобирается автоматически при каждом изменении в `main`
(GitHub Actions, `.github/workflows/build-windows.yml`). Кэш, портреты
героев и конфиг GSI приложение хранит рядом с собой, в папке `_internal`.

**Windows, из исходников:** двойной клик по `start.bat` в корне проекта. Скрипт сам найдёт
Python, при первом запуске поставит пакеты для чтения экрана и откроет браузер.
Должно открыться чёрное окно консоли.

Если вместо консоли открывается VS Code или «Блокнот» — это не ошибка скрипта,
а привязка расширения `.bat` в Windows: файл открывается на редактирование
вместо запуска. Любой из способов ниже решает задачу:

- Shift + правый клик по пустому месту в папке → «Открыть окно PowerShell здесь»,
  затем набрать `.\start.bat`
- правый клик по `start.bat` → «Открыть с помощью» → «Выбрать другое приложение»
  → `C:\Windows\System32\cmd.exe` → поставить галочку «Всегда»
- создать ярлык: правый клик → «Создать ярлык», в свойствах ярлыка в поле
  «Объект» написать `cmd /c "полный\путь\start.bat"`

**macOS и Linux:**

```
python3 app/server.py
```

Браузер откроется сам на `http://127.0.0.1:8777`. Основная часть работает
на одной стандартной библиотеке Python 3; пакеты нужны только для чтения экрана.

Полезные ключи:

```
python3 app/server.py --port 9000      # другой порт
python3 app/server.py --no-browser     # не открывать браузер
```

Сбросить кэш данных: открыть `http://127.0.0.1:8777/api/cache/clear`.

## Если что-то не работает

Запустите диагностику — она проверяет каждое звено по отдельности и говорит,
где именно затык: версия Python, пакеты, DNS, доступ к `api.opendota.com`
двумя разными способами, CDN с портретами, файлы приложения, занятость порта.

**Windows:** `diagnose.bat`
**macOS и Linux:** `python3 app/tools/diagnose.py`

Самая частая причина пустого интерфейса — нет доступа к `api.opendota.com`.
Без него приложение работать не может: оттуда берутся все данные о матчапах,
винрейтах и позициях.

## Что умеет

**Драфт.** Выбираете героев противника, своих и забаненных. Приложение выдаёт
топ героев с разбивкой: сколько даёт контрпик, сколько — базовая сила героя
в выбранном ранге, и против кого именно герой хорош. Есть фильтр по роли и рангу.

**Мета.** Таблица всех героев: винрейт и доля пиков в выбранном ранге,
про-пики, про-баны, про-винрейт.

**Турниры.** Пики, баны, спорность и винрейт каждого героя в турнирных
матчах за 1, 3 или 6 месяцев — по уровню турниров или по одному конкретному.
Считается напрямую по базе матчей OpenDota (`/explorer`): поля `pro_pick`
в справочнике героев почти пустые, а здесь — полторы тысячи матчей за квартал.

**Про-матчи.** Лента последних профессиональных игр. По клику — порядок пиков
и банов обеих команд, статистика игроков, предметы каждого героя (стартовый
закуп, сборка с минутами покупки, итоговый инвентарь) и оценка, чей драфт был
удобнее по историческим матчапам. Матч грузится тремя короткими запросами
к базе OpenDota, а не одним JSON на 45 КБ: на слабых каналах большой ответ
обрывался и не доходил никогда.

В подборе турнирная статистика участвует как третья составляющая балла
с настраиваемым весом («приоритет» / «умеренно» / «не учитывать»).

**Чтение экрана.** Приложение само узнаёт героев на экране драфта и
подставляет их в драфт. Героя, выбранного вручную, оно не перезаписывает.

## Чтение экрана

Нужны пакеты из `app/requirements-vision.txt` (на Windows их поставит
`start.bat`). Без них приложение работает как обычно, вкладка просто скажет,
чего не хватает.

Порядок работы:

1. Нажмите **«Скачать портреты»** — один раз качается 127 эталонов героев
   (около 9 МБ). Дальше сеть для распознавания не нужна.
2. Выберите монитор, область экрана и свою сторону (слева или справа).
3. **«Сканировать сейчас»** — разовый поиск, удобно проверить настройку.
4. **«Включить слежение»** — приложение будет опрашивать экран само.

### Как это устроено

Распознавание двухфазное, потому что честный полный поиск слишком медленный,
чтобы гонять его каждую секунду:

- **Калибровка** — поиск портретов по кадру в разных масштабах. Около
  3 секунд на верхней половине экрана, выполняется один раз за драфт.
  Масштаб подбирается по верхней полосе кадра, начиная с ожидаемой ширины
  портрета (6,4% ширины экрана при 16:9).
- **Слежение** — повторный поиск только при изменении полосы с портретами,
  в трёх масштабах вокруг известного.

Сравнивается только **верхняя часть портрета** (45%): в верхней полоске
Dota нижняя часть закрыта плашкой ранга и именем игрока, и с полным
эталоном на настоящем экране не находилось ничего. После уверенного
ряда пустые слоты между найденными героями досматриваются прицельно:
шаг между портретами одинаковый, и в слоте сравниваются все эталоны.
Так возвращаются герои, у которых лучшее совпадение по всему кадру пришлось
на мусор.

Проверено на настоящих скриншотах стадии выбора: 9 из 9 и 10 из 10 героев,
пустой слот (игрок ещё без героя) не подхватывается. Что отсекает
ложные срабатывания:

- **цвет** — сравнение идёт по цветной подписи, а не по градациям серого;
  плюс проверка насыщенности: портрет героя цветной, интерфейс и текст почти
  серые. Это оказалось решающим: без цвета на обычном рабочем столе стабильно
  «находились» три-четыре несуществующих героя;
- **геометрия** — портреты драфта стоят в один ряд, а ложные срабатывания
  разбросаны по кадру. Уверенность их не разделяет, геометрия разделяет;
- **минимальный размер** портрета относительно ширины экрана;
- **двойная проверка** — детекция принимается, только если поиск по шаблону
  и классификация цветной подписи назвали одного и того же героя.

### Ограничения чтения экрана

- Проверено на двух скриншотах стадии выбора (1280×743 после сжатия
  мессенджером) и на постороннем экране (ноль ложных срабатываний).
  Вживую, кадр за кадром на Windows — ещё нет. Пороги распознавания собраны
  в начале `app/vision/recognize.py`.
- На экране выбора героя с сеткой всех героев при области «весь экран»
  находятся портреты из сетки — держите область «верхняя половина».
- Приложение не читает память игры и никак с ней не взаимодействует: оно
  просто смотрит на картинку экрана, как сторонний зритель.
- Сторона (свои или враги) определяется по положению портретов на экране,
  а не по данным игры. Если стороны определились наоборот — переключите
  «Моя сторона».

## Безопасно ли это для аккаунта

Приложение никак не вмешивается в игру, и это принципиально:

- **не читает и не пишет память процесса Dota** — именно это ловит VAC;
- **не внедряет ничего в игру** — ни DLL, ни хуков, ни оверлеев внутри процесса;
- **не нажимает ничего за вас** — никакого автопика и автоматизации ввода;
- **не меняет файлы игры**, кроме одного: конфига Game State Integration
  в папке `cfg/gamestate_integration/`, которая Valve создана именно для
  сторонних программ — так работают стримерские оверлеи и виджеты.

Что оно делает: смотрит на картинку экрана через системный API (как OBS
или Discord при демонстрации экрана), принимает JSON, который игра сама
шлёт по официальному механизму GSI, и ходит в публичный API OpenDota.

Гарантию может дать только Valve, но всё перечисленное — публичные и
официально поддерживаемые каналы, а не обход защиты.

## Свой герой и сборка

Приложение показывает стартовый закуп, порядок сборки по минутам,
ситуативные и итоговые предметы вашего героя — по агрегату турнирных матчей
за выбранный период. Считается одним запросом к базе OpenDota, ответ
единицы килобайт.

Кто ваш герой, узнаётся тремя способами, от лучшего к простому:

1. **Game State Integration** — два шага. Кнопка «Подключить игру» кладёт
   конфиг в папку Dota (или «Скачать конфиг» и положить вручную в
   `dota 2 beta\game\dota\cfg\gamestate_integration\`). И в Steam у Dota 2
   нужен параметр запуска **`-gamestateintegration`** (библиотека → Dota 2 →
   правый клик → Свойства → Параметры запуска) — без него игра папку
   с конфигами не читает вовсе. После перезапуска игра сама сообщает героя
   и сторону, сообщения идут уже из главного меню. Кнопка «Проверить
   подключение» показывает, на каком шаге затык. Проверено имитацией
   сообщения игры; вживую с Dota — нет.
2. **Кнопка «это я»** на распознанном союзнике.
3. **Выбор из списка** вручную.

## Мой аккаунт

Подбор учитывает, на ком вы сами играете лучше: личный винрейт на герое
относительно вашего общего, сжатый по числу игр, и опыт на герое — тот, кого
вы ни разу не брали, получает минус, основной герой — плюс. Вес переключается:
учитывать / приоритет / не учитывать.

Аккаунт задаётся ID, Steam64 или ссылкой на профиль OpenDota, Dotabuff,
steamcommunity.com/profiles. Если игра подключена через GSI, аккаунт
подхватывается сам. Нужна включённая в Steam «Открытая история матчей»,
иначе OpenDota об игроке ничего не знает — приложение об этом скажет.

## Откуда данные

**OpenDota API** — публичный, ключ не нужен. Ответы кэшируются в `app/.cache`,
чтобы не упираться в лимит 60 запросов в минуту.

### Снимки данных в репозитории

В `app/data/` лежат снимки, с которыми приложение работает **без обращений
к OpenDota**:

| Файл | Что | Обновить |
|---|---|---|
| `herostats_fallback.json.gz` | справочник героев, винрейты по рангам | `python3 app/tools/update_fallback.py` |
| `matchups_fallback.json.gz` | матчапы всех героев, 16 тысяч пар | `python3 app/tools/update_matchups.py` |
| `positions.json` | позиции героев из про-матчей | `python3 app/tools/update_positions.py` |

Зачем это нужно: на некоторых каналах `api.opendota.com` отдаёт данные
со скоростью около 2 КБ/с — замерено на реальной машине. Один запрос стоил
20–40 секунд, а драфт из пяти врагов — минуты. Приложение выглядело зависшим.

Порядок для матчапов теперь такой: свежий кэш → снимок (мгновенно, обновление
из сети уходит в фон) → и только если снимка нет, ждём сеть. Подбор считается
за миллисекунды, а данные подтягиваются свежие, когда сеть позволяет.

Снимки стоит пересобирать раз в патч.

Про **d2pt.com** (dota2protracker.com): автоматический сбор оттуда не делается
осознанно. В `robots.txt` сайта стоит `Disallow: /` для ClaudeBot, GPTBot,
CCBot и других агентов, а также сигнал `ai-train=no`. Сайт закрыт Cloudflare,
и большая часть данных доступна только по подписке.

Ближайший легальный аналог данных d2pt — **STRATZ API** (бесплатный ключ после
регистрации): там есть матчапы с разбивкой по рангу и по позиции, чего
у OpenDota нет. Слой источников сделан сменным: нужно дописать
`app/sources/stratz.py` по интерфейсу `HeroSource` и поменять одну строку
в `app/sources/__init__.py`.

## Как считается оценка

```
score(H) = W_MATCHUP * среднее(adv(H, e) по врагам e) + W_BASE * (winrate(H) − средний winrate)
```

`adv(H, e)` — насколько H лучше играет против e, чем e играет в среднем.
Берётся из таблицы матчапов e: если e против H побеждает реже обычного,
значит H его контрит.

Веса и границы — в начале `app/scoring.py`.

### Почему среднее, а не сумма

Складывать пять матчапов — значит утверждать, что они независимы и
складываются один к одному. Это неверно и завышает оценку в разы.
На порядок героев среднее не влияет (делитель у всех одинаковый),
зато число остаётся интерпретируемым.

### Сглаживание

Матчапы OpenDota — это публичные матчи: около 9000 игр на героя,
распределённых по 126 соперникам. Отсюда медиана всего ~30 игр на пару,
а при n=30 разброс винрейта примерно ±9 процентных пунктов — сырое число
почти ничего не значит.

Поэтому каждое преимущество умножается на `n / (n + K)`, где K оценивается
по самим данным (эмпирический байес):

```
Var(наблюдаемое) ≈ Var(истинное) + среднее(p(1-p)/n)
K = p(1-p) / Var(истинное)
```

На текущих данных получается разброс истинного эффекта около ±6 п.п. и K
в районе 50–70. Значение K показывается под таблицей рекомендаций: чем оно
больше, тем сильнее в данных шум.

Оценку DerSimonian–Laird здесь применять нельзя: объёмы выборок различаются
в сотни раз, её знаменатель вырождается, и она выдаёт разброс ±43 п.п.,
то есть заведомо абсурдный.

## Чего приложение не умеет

- **Синергии между своими героями.** OpenDota не отдаёт винрейт пар героев
  в одной команде. Свои герои учитываются только как «эти уже заняты».
- **Разбивки по позициям.** Керри Mirana и саппорт Mirana для OpenDota — один
  и тот же герой. Это как раз то, что решается переходом на STRATZ.
- **Ранга Immortal.** Поле `8_pick` у OpenDota сейчас пустое, поэтому Immortal
  в списке рангов не появляется. Если запросить ранг без данных через API,
  ответ честно откатится на «Все ранги» и вернёт поле `note` с пояснением.
- **Профессиональной меты как отдельного режима.** Полей `pro_pick`/`pro_win`
  хватает примерно на тысячу игр по всем героям — слишком мало.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/heroes` | справочник героев и доступные ранги |
| POST | `/api/recommend` | подбор против драфта |
| GET | `/api/meta?bracket=&role=` | таблица меты |
| GET | `/api/pro/matches` | лента про-матчей |
| GET | `/api/pro/match?id=` | разбор матча |
| GET | `/api/cache/clear` | сбросить кэш |
| GET | `/api/vision/status` | доступно ли чтение экрана, мониторы, эталоны |
| GET | `/api/vision/state` | что сейчас видно на экране |
| POST | `/api/vision/icons` | скачать эталонные портреты |
| POST | `/api/vision/config` | монитор, область, интервал опроса |
| POST | `/api/vision/scan` | разовый поиск героев на экране |
| POST | `/api/vision/start` · `/stop` | включить и выключить слежение |

Пример запроса подбора:

```
curl -X POST http://127.0.0.1:8777/api/recommend \
  -H 'Content-Type: application/json' \
  -d '{"enemy":[1,8,44],"bracket":"7","limit":10}'
```
