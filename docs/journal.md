# Журнал сессий

Общая память для Claude Code на Mac и ПК. Каждая сессия при старте читает
последнюю запись (это делает хук автоматически), а в конце работы дописывает
свою — **новые записи снизу**, коммит и push. Формат записи:

```
## ДАТА · машина (mac / pc) · коротко о чём сессия

**Сделано:** что изменилось и где (файлы, коммиты).
**Проверено:** что реально запускалось и что показало.
**Открыто:** что не доделано, что сломано, какие гипотезы.
**Следующий шаг:** одна строка — с чего начинать следующей сессии.
```

Запись — не отчёт и не пересказ диалога: только то, что нужно, чтобы
продолжить с другой машины. Подробности — в коммитах и `docs/handoff_*.md`.

## 2026-09-14 · pc · окно на Windows починено: дело было в метке MOTW

**Сделано:** причина «браузер вместо окна» найдена и устранена, версия `.8`.
Это не кириллица: обход `.7` отрабатывал верно, DLL бралась из копии по
ASCII-пути, и всё равно падало. Настоящая причина — метка «скачано из
интернета» (`Zone.Identifier`), .NET отказывается грузить помеченную
сборку (HRESULT `0x80131515`); помечены были 311 файлов из 314. Обход `.7`
не спасал, потому что `shutil.copytree` через `CopyFile2` переносит и
альтернативные потоки — метка ехала в ASCII-папку вместе с DLL.
`app/window.py`: `_dotnet_runtime_workaround` снимает метку со всей
`_internal` и с копии runtime (ASCII-обход оставлен). `build-windows.yml`:
проверка запуска сама метит файлы — CI этого не ловил, потому что сборка
на раннере локальная и метки на ней нет. `server.py`: подсказка про
«Разблокировать». `diagnose.py`: раздел 6 — pywebview, .NET, WebView2,
метки, кириллица в пути.

**Проверено на pc:** exe `.7` из «Рабочего стола» — снят вывод консоли,
`Failed to resolve …` при ASCII-пути копии; `Assembly::LoadFrom` дал
`0x80131515`; после `Unblock-File` сборка грузится и `Loader.Initialize`
резолвится; exe запущен заново — **окно открылось**, WebView2 поднялся,
страница пошла в API. `_unblock_tree` проверена на помеченных файлах
(снято 2 из 2). `diagnose.py` прогнан целиком, раздел 6 работает.
Сам exe версии `.8` ещё не собирался — это сделает CI.

**Открыто:** на ПК не было ни git, ни gh — поставлены через winget,
`gh auth login` сделан пользователем. Хук `session_start.sh` — shell-скрипт,
на Windows через PowerShell он не отработает, `git pull` пришлось делать
руками; если хук нужен на обеих машинах, ему нужен второй вариант.

**Следующий шаг:** дождаться сборки `.8`, скачать архив и проверить на ПК,
что окно открывается из скачанного архива без ручного `Unblock-File`.
