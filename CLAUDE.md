# Dota 2 Draft Helper — правила для Claude Code

Локальное приложение на Python (stdlib) + HTML/JS: подбор героев против
вражеского драфта. Описание, архитектура и статус — в `app/README.md` и
`_project_dota2_draft_helper.md`. Общение с пользователем — на русском; код,
комментарии и документы — тоже на русском.

## Две машины, один репозиторий

Над проектом работают по очереди с Mac и с Windows-ПК, в одной ветке `main`.
Общей памяти между машинами у Claude Code нет — единственный общий канал
это git. Поэтому:

**При старте** (хук `SessionStart` делает это сам): `git pull --ff-only`,
в контекст попадают последние коммиты и последняя запись `docs/journal.md`.
Если хук сообщил, что pull не прошёл — разобраться с этим до любой работы.

**Перед завершением работы** (когда пользователь прощается, говорит «всё»,
«на сегодня хватит», переходит на другую машину — или просто перед
длинной паузой):

1. Закоммитить всё сделанное. Незакоммиченное на другой машине не видно.
2. Дописать запись в конец `docs/journal.md` по формату из шапки файла:
   сделано / проверено / открыто / следующий шаг. Коротко, без пересказа
   диалога.
3. `git push`. Если push отвергнут — сначала `git pull --rebase`, потом
   снова push.

**Никогда** не коммитить токены и ключи (GitHub PAT, STRATZ). Файл
`stratz_token.txt` в `.gitignore`; секреты CI — в GitHub Secrets.

## Что где

- `app/server.py` — сервер и маршруты; `app/window.py` — окно pywebview;
  `app/scoring.py` — модель подбора; `app/sources/` — OpenDota и STRATZ.
- `app/data/*.json.gz` — снимки данных; пересобираются скриптами из
  `app/tools/`. Снимок STRATZ обновляет CI по пятницам.
- `.github/workflows/build-windows.yml` — exe на каждый push в `main`,
  релиз `latest`. Проверка запускает exe с окном из папки с кириллицей.
- `docs/journal.md` — журнал сессий; `docs/handoff_*.md` — подробные
  передачи, когда одной записи в журнале мало.

## Как проверять

- Из исходников: `python3 app/server.py` (`--browser`, `--no-browser`,
  `--port`). Окно требует `pip install -r app/requirements-window.txt`.
- Exe проверяет CI: лог шага «Проверка запуска» печатает вывод exe
  целиком. Версия — первая строка консоли (`VERSION` в `server.py`);
  поднимать при каждом изменении, попадающем в exe.
- На Mac нет Windows, на ПК нет macOS — то, что проверено только на одной
  машине, так и писать: «проверено на mac / на pc / только на раннере».

## Стиль работы

- Одна команда — один вызов Bash; без `&&`, `;`, heredoc и циклов в шелле.
  Логика — в скриптах (Python) в scratchpad.
- Уточняющие вопросы — только если разные трактовки дают материально
  разный результат; иначе принять допущение, назвать его и делать.
- Не выдавать непроверенное за проверенное. Если не запускал — так и
  говорить.
